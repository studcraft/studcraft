## Why

`delete-me-review.md` requests a whole-ruleset consistency pass before a 1.0 release (REVIEW-018 through REVIEW-021): standardize terminology, verify each document owns only its intended responsibility, unify architecture diagrams, and do a final language pass. Unlike the prior three review files (all scoped to `11-combat.md`/`12-melee.md`), this one asks for a repo-wide check — so the work here is a full re-verification across all 15 `docs/*.md` files, not just the two already under review.

## What Changes

- **REVIEW-019 (ownership) found one real violation**: `docs/08-vehicles.md` VEH-014 ("Weapon Systems") independently restated "each visible weapon is treated as an independent weapon system... resolves attacks independently" — a third copy of the exact concept `10-weapons.md` WPN-008 and `11-combat.md` CBT-006 already own (CBT-006 already cross-references WPN-008; VEH-014 cross-referenced neither). Reduced to a one-line cross-reference to both.
- **REVIEW-020 (diagram consistency) found real drift**: three flow diagrams existed with different vocabulary for the same sequence — `11-combat.md`'s Combat Flow (most current), `16-damage-system.md` DMG-009's "Combat Resolution Overview" (used "Generate Impacts"/"Select Component," pre-dated the Delivery Method/melee unification work entirely), and `12-melee.md`'s Design Philosophy diagram (said "Generate Impact" instead of "Generate Attack Dice"). All three now use identical step names for the same concepts. `11-combat.md`'s diagram also gained an explicit "Successful Impacts" step (citing `CBT-005`, whose own title this is) between "Attack Roll" (`DMG-011`'s title, the same mechanic viewed from the damage-resolution sequence) and "Component Damage System" — previously "Attack Roll" was mislabeled with `CBT-005`'s ID.
- **REVIEW-018 (terminology)**: verified every term in the review's list — Weapon, Weapon System, Functional Muzzle, Functional Striking End, Delivery Method, Attack Dice, Attack Roll, Impact, Impact Strength, Component, Resistance, Geometry Check, Damage Roll, Component State, Penetration — is used consistently everywhere it appears, with exactly one canonical definition each (all previously-found synonym issues were already fixed by prior findings). No further action needed beyond the VEH-014 fix above.
- **REVIEW-021 (final language pass)**: checked "physically removed" vs. "removed from the model" and "determines" vs. "defines" for unwanted synonym drift. Both are naturally-varying, contextually-correct English (illustrative examples use varied phrasing; "defines" states a document/rule's scope, "determines" states a causal/derived relationship) — not two names competing for one concept. No change made; forcing uniform wording here would reduce readability without removing any actual ambiguity.

## Impact

- `docs/08-vehicles.md` (VEH-014), `docs/11-combat.md` (Combat Flow diagram), `docs/16-damage-system.md` (DMG-009), `docs/12-melee.md` (Design Philosophy diagram) edited. No rule ID added, removed, or renumbered.
- No change to any measured rule value, dice mechanic, or resolution sequence — this is documentation-consistency work only.
