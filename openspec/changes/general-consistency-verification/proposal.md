## Why

`delete-me-review.md` requests a whole-ruleset consistency pass before a 1.0 release (REVIEW-018 through REVIEW-021): standardize terminology, verify each document owns only its intended responsibility, unify architecture diagrams, and do a final language pass. Unlike the prior three review files (all scoped to `11-combat.md`/`12-melee.md`), this one asks for a repo-wide check — so the work here is a full re-verification across all 15 `docs/*.md` files, not just the two already under review.

## What Changes

- **REVIEW-019 (ownership) found one real violation**: `docs/08-vehicles.md` VEH-014 ("Weapon Systems") independently restated "each visible weapon is treated as an independent weapon system... resolves attacks independently" — a third copy of the exact concept `10-weapons.md` WPN-008 and `11-combat.md` CBT-006 already own (CBT-006 already cross-references WPN-008; VEH-014 cross-referenced neither). Reduced to a one-line cross-reference to both.
- **REVIEW-020 (diagram consistency) found real drift**: three flow diagrams existed with different vocabulary for the same sequence — `11-combat.md`'s Combat Flow (most current), `16-damage-system.md` DMG-009's "Combat Resolution Overview" (used "Generate Impacts"/"Select Component," pre-dated the Delivery Method/melee unification work entirely), and `12-melee.md`'s Design Philosophy diagram (said "Generate Impact" instead of "Generate Attack Dice"). All three now use identical step names for the same concepts. `11-combat.md`'s diagram also gained an explicit "Successful Impacts" step (citing `CBT-005`, whose own title this is) between "Attack Roll" (`DMG-011`'s title, the same mechanic viewed from the damage-resolution sequence) and "Component Damage System" — previously "Attack Roll" was mislabeled with `CBT-005`'s ID.
- **REVIEW-018 (terminology)**: verified every term in the review's list — Weapon, Weapon System, Functional Muzzle, Functional Striking End, Delivery Method, Attack Dice, Attack Roll, Impact, Impact Strength, Component, Resistance, Geometry Check, Damage Roll, Component State, Penetration — is used consistently everywhere it appears, with exactly one canonical definition each (all previously-found synonym issues were already fixed by prior findings). No further action needed beyond the VEH-014 fix above.
- **REVIEW-021 (final language pass)**: checked "physically removed" vs. "removed from the model" and "determines" vs. "defines" for unwanted synonym drift. Both are naturally-varying, contextually-correct English (illustrative examples use varied phrasing; "defines" states a document/rule's scope, "determines" states a causal/derived relationship) — not two names competing for one concept. No change made; forcing uniform wording here would reduce readability without removing any actual ambiguity.

- **Second pass, before merging**: re-reviewed the diff itself and found one internal inconsistency in the diagram fix — `11-combat.md`'s diagram cited `CBT-005` inline on "Successful Impacts" while its same-document neighbors ("Generate Attack Dice" → `CBT-004`, "Attack Roll" → `DMG-011`/`CBT-005`) went uncited. Removed the citation to match the established pattern (only cross-document steps get inline citations).
- **Third pass, following up on `remove-materials-document`**: a case-insensitive repo-wide grep for "material"/"materials" (the earlier case-sensitive grep during `remove-materials-document` missed lowercase occurrences) found several more stale references left behind by that change:
  - `docs/14-glossary.md`: the "Material" entry ("Determines how a component resolves Impacts") directly contradicted `DMG-008` ("No Material-Specific Mechanics") — removed entirely, since no game concept called "Material" exists anywhere else in the ruleset anymore. The "Impact" entry's "Targets resolve Impacts according to their Material" was also stale — updated to cite the Component Damage System.
  - `docs/01-foundations.md`: "Universal Systems" list still included "Materials" as one of StudCraft's core systems; the "Impacts" section said targets resolve Impacts "according to its material and construction" and that "materials behave differently" — all updated to reflect that construction (Resistance) alone determines resolution now, with no material-specific behavior.
  - `docs/10-weapons.md` WPN-016 (Weapon Damage): dropped "Materials" from its "final effect depends on" list.
  - `CODE_OF_DESIGN.md`: Principle 5, Principle 10, and Principle 15 each referenced Materials/Material Responses as if they still existed — updated to the Component Damage System.
  - `CONTRIBUTING.md`: its Repository Structure tree still listed `13-materials.md` — and was missing `15-geometry-layers.md`/`16-damage-system.md` entirely, a staleness that predates `remove-materials-document`. Fixed both.
  - `system/proposal-review.md`: its own "read every neighboring document" guidance told future reviewers to check "materials" when reviewing weapons/damage proposals — the exact advice that would have caught `VEH-014` if it had said "every document" instead of naming specific neighbors. Updated to reference melee/vehicles instead of the removed document, and added a note recording the `VEH-014` lesson explicitly.
  - Not touched (correctly): `CHANGELOG.md`'s historical `[0.1.0]` entry (frozen record of what shipped in the past — Materials genuinely existed at that version), `openspec/specs/damage-resolution/spec.md`'s pending `13-materials.md` citation (this is the *not-yet-archived* baseline spec; `remove-materials-document`'s own delta already fixes this, waiting on a batched Archive cut, not a bug to hand-edit), and every `openspec/changes/*/` proposal/design/tasks file that mentions "materials" while historically documenting the removal decision itself.

- **Fourth pass, `docs/06-deployment.md`** (requested separately, `docs/` documents not yet re-read this round): `DEP-004` (Infantry) and `docs/09-transport.md` `TRN-002` (Infantry Occupancy) both independently restated "infantry occupies 1 Unit Base" with no cross-reference to `02-core-rules.md` CORE-003, which already states this exact fact. This is the same duplication class `consolidate-core-measurements` (a prior, separate proposal) already fixed for the *size* of a Unit Base (every `docs/*.md` reference to "4 × 3 studs" now cross-references `CORE-001`) — but that consolidation didn't cover the separate fact that infantry specifically occupies exactly one of them, which `CORE-003` also already states. `DEP-004` and `TRN-002` now cross-reference `CORE-003` instead of repeating it, keeping their own unique elaboration (deployment flexibility; posture-invariance and what's included in the occupied space).
